# Withdrawing

<p className="lede">
  Burn shares, receive SOL at the current redemption ratio. No lockup, no exit fee. The only constraint is liquidity.
</p>

<Callout kind="tldr">
  **tl;dr —** `withdraw(shares)` → shares burned from your `DepositorRecord` → SOL transferred from the vault to your wallet at `vault_balance / total_shares` per share.
</Callout>

## No lockup

Deposits are not locked. There is no cooldown, no withdrawal queue, no exit fee, and no maturity date. You can deposit and withdraw in the same block if you want.

## The liquidity catch

Withdrawals are limited by the **idle** vault balance, not the full vault balance.

```
idle = vault_balance - total_loans_outstanding
```

SOL that's out as active loans is reserved until those borrowers repay (or the loans expire and the rent is reclaimed). If you try to withdraw more than `idle`, the transaction reverts with `InsufficientLiquidity` (error 6003).

This is the normal trade-off for a peer-to-pool lender: high utilization is great for yield, less great for instant exits.

<Callout kind="warn">
  **There is no auto-queue.** If you hit `InsufficientLiquidity`, you have to wait, retry, and request a smaller amount. The protocol won't park your request and fill it later.
</Callout>

## Partial vs full

`withdraw` takes a `shares` argument, so you can redeem any portion of your balance. Two common patterns:

- **Partial:** redeem a specific share amount you've computed off-chain (e.g. "withdraw 25% of my position").
- **Full:** read your current `share_amount` and pass that. The instruction will burn all of them and close the math out.

The `Withdrawn` event includes `remaining_shares` so you can confirm:

```
{
  depositor: <your pubkey>,
  amount: <lamports you received>,
  shares_burned: <shares burned>,
  remaining_shares: <shares left on your record>
}
```

## Doing it

The web app at [app.solignition.xyz](https://app.solignition.xyz) handles withdrawals: pick an amount in SOL, the app converts to shares using the current ratio, and submits the tx.

Programmatically:

```ts
await program.methods
  .withdraw(new BN(shares_to_burn))
  .accounts({ depositor: wallet.publicKey })
  .rpc()
```

## What can go wrong

| Error | Cause |
|---|---|
| `InvalidAmount` (6001) | Passed `0` shares or a value larger than your balance. |
| `InsufficientLiquidity` (6003) | The idle vault balance can't cover the redemption. Wait or withdraw less. |
| `UnauthorizedDepositor` (6014) | Signer isn't the `owner` of the `DepositorRecord` you're trying to burn from. |
| `ProtocolPaused` (6000) | Admin paused the protocol. |
