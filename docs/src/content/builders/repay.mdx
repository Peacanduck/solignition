# Repaying loans

<p className="lede">
  Repay before the loan expires. You owe principal plus time-prorated interest. The admin fee was already paid upfront and is not part of repay.
</p>

<Callout kind="tldr">
  **tl;dr —** `solignition repay <LOAN_ID>` → wallet debited for principal + interest → state moves to `RepaidPendingTransfer` → the deployer transfers upgrade authority → state moves to `Repaid`.
</Callout>

## What you owe

Two amounts:

- **Principal** — the lamports originally disbursed from the vault. Stored in `Loan.principal`.
- **Interest** — computed at repay time:

```
elapsed = now - loan.start_ts
interest = (principal × interest_rate_bps × elapsed) / (10_000 × duration)
```

That's it. The admin fee is not part of repay — it was paid at `request_loan` and lives in `Loan.admin_fee_paid` for the record.

For the full derivation and a worked example, see [Interest math](/protocol/interest).

## Doing it

```bash
# Inspect first — shows current owed
solignition status 148

# Pay (interactive confirm)
solignition repay 148

# Pay (non-interactive)
solignition repay 148 -y
```

`solignition loans` lists every loan you've opened with its current state, so you can find IDs you forgot.

## State transitions

| Before | After | Caused by | What flips |
|---|---|---|---|
| `Active` | `RepaidPendingTransfer` | You: `repay_loan` | `repaid_ts` set, `interest_paid` set, SOL moved to vault + admin split, state changed |
| `RepaidPendingTransfer` | `Repaid` | Deployer: `transfer_authority_to_borrower` | Upgrade authority CPI'd to your wallet, state changed |

The second step happens within seconds in normal operation. Until it completes, your program still has the escrow PDA as upgrade authority — you can't upgrade yet.

## Early repay

Repaying early is **strictly cheaper** because interest is pro-rated to elapsed time. There's no penalty term, no minimum interest, no cancellation fee.

Numerical example, 30-day loan at 5% interest on 4 SOL principal:

| Held for | Interest | Total repay |
|---|---|---|
| 1 day | `0.00667 SOL` | `4.00667 SOL` |
| 7 days | `0.04667 SOL` | `4.04667 SOL` |
| 15 days | `0.1 SOL` | `4.1 SOL` |
| 30 days | `0.2 SOL` | `4.2 SOL` |

If you finish your work in week 2, repay then.

## Expiry

<Callout kind="warn">
  **There is no grace period.** Once `now > start_ts + duration`, `repay_loan` returns `LoanExpired` (error 6020). The loan is now eligible for `recover_loan` and your program will be closed. See [What if I default?](/builders/default).
</Callout>

Track expiry with `solignition status <id>`. The CLI shows time remaining.

## What can go wrong

| Error | Cause | Remedy |
|---|---|---|
| `LoanNotActive` (6007) | The loan is already repaid, recovered, or still pending deploy. | Check `solignition status <id>`. |
| `UnauthorizedBorrower` (6008) | Wrong signer. Only `Loan.borrower` can repay. | Use the keypair that opened the loan. |
| `LoanExpired` (6020) | Past expiry. | Too late. See [default flow](/builders/default). |
| `InsufficientBalance` (6002) | Wallet doesn't have principal + interest. | Top up and retry. |
